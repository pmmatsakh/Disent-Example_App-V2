How this platform works

The rules every example follows. Learned the hard way — each one here caused a real outage or a wasted deploy.

1. Routing is by PORT

https://my-container-{PORT}.example.com  →  container:{PORT}

The app name never appears in the hostname. Each app needs its own port — including static ones, which otherwise all collide on :80.

The retired scheme. {project}-{name}.fastcontainers.net is dead — that domain no longer resolves. If you find it in a file, it is a bug.

2. Bind 0.0.0.0, never 127.0.0.1

HOST = os.environ.get("HOST", "0.0.0.0")

The platform connects to container:{PORT} directly. A loopback-only listener passes every local test and still returns 502 at the edge. This is the single most common failure.

Databases are the deliberate exception — they stay on loopback and are reached through their tile, never exposed publicly.

3. Python uses uv

The container has no pip and python3 -m venv cannot build a usable environment (ensurepip missing).

uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt

uv lives at /root/.local/bin/uv, which is not on a non-interactive SSH PATH. The venv has no pip inside — uv is the installer — which is fine, since systemd only needs .venv/bin/python.

4. Node is pinned to 22

/root/.nvm/versions/node/v22.22.2/bin/node

/usr/bin/node is v18.19.1 and too old for Vite 8, Next.js 16 and the Codex CLI. Never put it in a unit.

5. Secrets

Git-ignored .env, loaded via systemd EnvironmentFile. Never hard-coded, never committed. Every app ships a .env.example.

deploy.sh regenerates the unit on every deploy, so an EnvironmentFile= line must be re-applied after a redeploy.

6. Deploying

./deploy-all.sh <name>        # one app
./deploy-all.sh                # everything

It runs a preflight that proves each toolchain by using it, copies into /srv/apps/, installs deps, then writes the unit and nginx conf and restarts. The verify step reports the bind address — that line is the one that matters.

Never test a capability with --help. python3 -m venv --help succeeds on a box where venv cannot create an environment. Check that a thing works, not that it exists.

7. Definition of done

Rendered in a real browser at the real subdomain. A local 200 proves nothing — the nodejs app returned 200 locally for weeks while every visitor got a 502.
